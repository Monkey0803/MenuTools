# 窗口管理运行时验收清单

> **验收记录**：2026-09-11 由用户在真机完成第 1–11 组全部验收（结果由用户确认，非脚本自动判定）。
> 其中第 11 组的 `menutools://` 链接触发另有脚本化端到端验证（见 README「用链接触发窗口操作」）。
> 后续系统大版本升级、或改动吸附/收纳/快捷键相关代码后，建议按本清单重跑一遍。

窗口管理模块的行为大量依赖辅助功能 API、全局鼠标监听和真实拖拽，单元测试覆盖不到。这份清单用于在真机上逐项验收，覆盖「已交付但从未在真机跑过」的功能。

建议先打开诊断日志（默认不写任何文件）：

```bash
touch /tmp/menutools-snap-debug     # 下次启动后写 /tmp/menutools-snap.log
rm /tmp/menutools-snap-debug        # 验收结束后关闭
```

前置条件：

- [x] 应用已重启到最新构建（`pkill -f MenuTools.app/Contents/MacOS/MenuTools; ./build.sh`）
- [x] 辅助功能权限已授予（窗口管理设置页没有橙色权限提示）
- [x] 准备两个普通窗口（例如一个浏览器窗口 + 一个文本窗口）；验收期间不要用全屏应用和台前调度

## 2. 固定尺寸预设

## 3. 预设快捷键

- [x] 给预设录制一个组合键 → 按一次即套用该预设

- [x] 删除该预设 → 其快捷键不再触发；重新打开设置页后绑定已被清理

## 4. 同族布局循环

- [x] 给「第一列三分之一」绑快捷键 → 连按：第一列 → 中间列 → 最后一列 → 回到第一列

- [x] 关闭设置页「连按同一快捷键循环切换同族布局」→ 连按不再切换

- [x] 从没有套用过任何布局的新窗口触发「恢复」→ 给出「还没有保存的窗口尺寸」提示，不崩溃

## 出问题时

1. 看 `/tmp/menutools-snap.log`（需要先 `touch /tmp/menutools-snap-debug` 并重启应用）：能看到命中测试结果、标题栏判定、预览落点、松手吸附每一步
2. 跑 `swift Scripts/test_window_management.swift --interactive`：确认辅助功能权限、多显示器几何、AX 读写是否正常
3. 把日志片段 + 复现步骤 + 期望结果一起反馈
