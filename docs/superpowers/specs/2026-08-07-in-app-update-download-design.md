# 应用内更新下载设计

## 目标

在 `1.0.2` 分支中让 MenuTools 在 App 内下载 GitHub Release 安装包。下载完成后由用户确认并使用系统默认程序打开安装包；不自动替换当前 App、不提权、不强制重启。

## 用户流程

1. 用户点击“下载更新”。
2. App 在临时目录创建下载任务并显示进度。
3. 下载完成后校验响应和支持的安装包扩展名。
4. 用户确认后打开 zip、dmg 或 pkg 文件。
5. 用户取消、下载失败或打开失败时，当前 App 继续运行并显示本地化错误。

## 架构

- `UpdateCheckerService` 继续负责版本检查、Release/appcast 解析和下载 URL 提供。
- 新增 `UpdateDownloadService` 负责下载任务、状态转换、进度和取消。
- 文件下载、临时文件移动和安装包打开通过协议边界注入，纯状态与错误处理可用 Swift Testing 验证。
- 菜单栏面板和设置页共用下载状态逻辑；两处入口都显示“下载更新”和下载中状态。

## 安全边界

- 下载 URL 必须是有效 URL，HTTP 响应必须为成功状态。
- 只接受 `.zip`、`.dmg`、`.pkg` 安装包资产。
- 下载文件只写入系统临时目录，不写入 App 安装目录。
- 不执行下载内容，不调用 shell，不使用 sudo，不自动覆盖或重启当前 App。

## 验收标准

- 新版本入口能在 App 内开始下载并显示进度。
- 同一时间不能启动多个下载任务；用户可以取消下载。
- 下载成功后，用户确认即可打开临时目录中的安装包。
- 非法 URL、非成功 HTTP 响应、非支持扩展名、取消和文件错误均不会破坏当前 App。
- Swift Testing、release build 和 App 打包通过。
